# Database

PostgreSQL stores UUID primary keys generated by SQLAlchemy. Creation and event timestamps use timezone-aware columns. User-facing calendar dates are stored as dates calculated in the user's timezone. Keep historical local dates stable when the user changes timezone.

| Table | Purpose and key constraints |
| --- | --- |
| users | Unique normalized email and Argon2id password hash |
| user_settings | One settings row per user, with a timezone and week start from 0 (Monday) to 6 (Sunday) |
| goals | Owner, optional target date, optional completion time |
| projects | Owner and optional same-owner goal |
| tasks | Owner and optional same-owner project. Scheduled date supports daily and weekly range queries, separate from the due timestamp |
| habits | Owner and optional archive time |
| habit_logs | One completed entry per habit per local date. Ordered dates support streak calculations |
| focus_sessions | Owner, indexed start time, and optional end time strictly after start |
| daily_statistics | One row per owner and local date. Nonnegative activity totals and optional score from 0 to 100 |
| evening_reflections | One row per owner and local date, with notes and optional mood from 1 to 5 |
| refresh_sessions | Owner, absolute expiration, optional revocation time |
| refresh_credentials | Unique SHA-256 token digests with at most one unconsumed credential per session |

User deletion cascades to owned records. Deleting a habit or refresh session cascades to its logs or credentials. Projects and tasks can be unlinked before their parent goal or project is deleted. Composite foreign keys enforce that linked rows belong to the same account. Composite unique constraints supply the referenced owner and ID pairs. Ordered indexes support owner-scoped schedules, habit history, focus queries, and expired-session cleanup.

Future recommendations, achievements, notifications, XP, and accountability records can reference stable users and domain UUIDs with their own lifecycles and authorization rules.

## Phase 2 migration

Revision `0002` adds descriptions and update timestamps to goals, projects, and tasks. Existing update timestamps are backfilled from creation time. Existing completed goals receive progress 100, with other goals starting at 0. Goal status derives from its completion timestamp. Project status derives from its archive timestamp, and task status derives from its completion timestamp.

The migration adds project date bounds, task schedule timestamps, and an optional same-owner task-to-goal foreign key. PostgreSQL checks enforce valid progress, completion consistency, and schedule ordering. A goal or project referenced by another record must be unlinked before deletion. Downgrading to `0001` preserves Phase 1 rows and removes Phase 2 fields and constraints.
